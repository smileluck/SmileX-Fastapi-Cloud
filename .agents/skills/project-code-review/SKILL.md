# 项目代码审查

对当前仓库的变更做完整、语义级的审查。目标不是挑风格问题，而是确认变更在契约、生命周期、错误路径和测试有效性上成立。

## 第一步：确认审查范围

- 确认 git 根、当前分支、base、脏状态与未跟踪文件
- 审查 committed、staged、unstaged 的全部相关改动
- 发生过 merge/rebase 后，重新确认 base 再审查
- 禁止只审查 `git diff` 的局部片段而忽略上下文

## 第二步：语义审查清单

逐项检查，发现问题必须给出文件与行号：

- **契约两侧**：被改动的接口/数据结构/配置的生产方与所有消费方是否同步；改名、删字段、改语义是否有遗漏的调用点
- **生命周期**：资源创建/销毁、取消路径、异步任务退出、订阅清理是否完整
- **错误报告**：错误是否被吞、被错分类、或丢失上下文；错误响应对调用方是否可预期
- **安全边界**：鉴权/授权是否在实际执行操作处强制，而非只在外层；输入校验是否覆盖新路径；禁止输出敏感信息
- **迁移与回滚**：持久数据、配置、wire 格式变更是否有迁移路径与回滚方式
- **状态归属**：保留状态是否有唯一权威 owner，是否存在双份维护
- **测试有效性**：验证相关测试会在预期回归上真的失败（而非恒绿）；测试是否断言了行为而非实现细节
- **文档一致性**：文档描述与行为、默认值、错误、配置项、公开接口是否一致——自动检查通过不证明文字准确

## 第三步：按影响面选择证据

| 变更类型 | 应跑的证据 |
|---|---|
| 逻辑改动 | 归属模块的聚焦测试；共享契约变更时补相邻测试 |
| 类型 / 公开接口改动 | typecheck + 消费方/契约测试 |
| 用户/模型可见输出 | 真实入口路径的冒烟（snapshot / E2E / 可运行示例） |
| 构建、导出、清单、生成物 | 构建 + 构建产物冒烟 |
| 文档 | 链接、格式、示例检查 |
| 集成行为 | 有凭据与授权时跑真实集成测试；禁止打印 secret |

- 禁止反射式跑全量测试；仅在仓库级变更、CI 诊断或用户明确要求时使用全量
- 禁止为变绿放宽过滤条件或阈值

## 第四步：报告纪律

- 报告精确命令与真实结果
- 结果分类：passed / failed / skipped / unavailable / not-run，禁止混报
- 中断的进程不是成功；以可观察的验收检查为准
- 输出格式：

```
## 审查结论
[通过 / 有阻断问题 / 有建议项]

## 阻断问题（必须修复）
- [文件:行号] 问题描述与建议

## 建议项（可选）
- [文件:行号] 问题描述

## 验证证据
| 命令 | 结果 |
|---|---|
| `...` | passed/failed/skipped/unavailable/not-run |

## 未覆盖的风险
[本次审查未能验证的部分]
```
