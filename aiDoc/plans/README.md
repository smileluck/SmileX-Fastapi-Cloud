# 变更计划（plans）

`aiDoc/plans/` 保存执行中的变更计划与交接文档。执行状态与决策理由的老化速度不同，因此计划（这里）与决策记录（[../notes/](../notes/)）分开维护。

## 目录结构

| 目录 | 内容 |
|---|---|
| `active/` | 正在进行中的变更计划，命名 `yyyy-mm-dd-topic.md` |
| `completed/` | 已完成并归档的计划 |

## 何时需要计划

以下工作必须在 `active/` 建立变更计划（使用 [change-plan.TEMPLATE.md](change-plan.TEMPLATE.md)）：

- 多步骤、跨组件的变更
- 有风险的变更（数据迁移、契约破坏、依赖升级）
- 需要分解给多个执行者或需要交接的工作

单文件、单接口的小改动无需计划，直接按根 `AGENTS.md` 的工程规则执行。

## 生命周期

1. 开工前在 `active/` 创建计划，写清目标/非目标/假设/验收标准/工作项/验证命令/回滚
2. 工作进展中就地更新计划（当前决策、阻塞、已完成项）
3. 完成时：在计划末尾补一段交付结果摘要，移入 `completed/`
4. 无长期留存价值的计划（纯临时协调）完成后可直接删除
5. 已完成的计划是执行证据，不是当前行为的权威描述——当前行为以代码与 aiDoc 子文档为准

## 工作项写法

- 每个工作项标注 owner 与依赖关系
- 写范围（write scope）是建议性的：标注预期改动的文件/目录，减少并行冲突，但不是锁
- 每个工作项附验证命令，按影响面选择证据（可用命令见 `.agents/skills/project-pre-push-checks/SKILL.md` 与 `../relations/development-workflow.md`）

## 交接

工作中断或移交他人时，使用 [handoff.TEMPLATE.md](handoff.TEMPLATE.md)。禁止把中断的命令描述为已完成；交接必须给出下一步安全动作。
