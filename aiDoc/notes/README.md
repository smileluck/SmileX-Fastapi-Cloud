# 决策记录（notes）

`aiDoc/notes/` 保存非平凡决策的动机、结论与后果。决策记录回答的是"为什么"，不是"当前是什么"——当前事实维护在对应 aiDoc 子文档中。

## 何时必须写决策记录

当变更涉及以下任一情况时，必须新增或更新一条决策记录：

- 行为变更（用户或可调用方可感知）
- 架构调整（分层、模块边界、依赖方向）
- 共享契约变更（API、数据格式、配置格式、持久数据结构）
- 流程 / 工具链变更
- 测试策略变更
- 其他可能被重新讨论或推翻的决策

## 目录结构与命名

```
notes/<lifecycle>/<class>/yyyy-mm-dd-topic.md
```

### 生命周期（lifecycle）

| 目录 | 含义 |
|---|---|
| `proposed/` | 已提出、尚在评审中的实质性工作 |
| `implemented/` | 已落地的现行决策；事实变化时就地更新，保持路径与内容最新 |
| `rejected/` | 被否决的提案；仅当其理由能防止重蹈覆辙时保留 |

### 分类（class）

`feature` / `bug-fix` / `simplification` / `architecture` / `process` / `testing`

只有项目出现真实分类缺口时才允许扩展新 class，且必须回本文件登记。

## 维护纪律

1. 使用 [TEMPLATE.md](TEMPLATE.md) 作为新记录模板
2. **禁止编造备选方案**：只记录真实考虑过的备选及其被放弃的理由
3. **implemented 不追加 changelog**：事实变化时就地更新正文；决策记录是现行结论的快照，不是历史流水
4. **推翻旧决策要新建 note**：新记录与旧记录互相交叉链接，旧记录移入 `rejected/` 或就地标注被取代
5. 决策被完全废弃且无防呆价值时，可删除对应记录
6. 每条决策记录必须写清验收标准 / 风险 / 后果，使后来者能独立判断该决策是否仍然成立
